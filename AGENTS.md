# LTMsav — read this first

## Minimal context workflow
1. Read `MAINTENANCE.md` (current state, risks, commands).
2. Use the task-to-file table in `đọc trước khi làm/APP_MAP.md`; open only affected files and their tests. Do not scan all `src` by default.
3. Read `DATA_SAFETY_RULES.md` before storage, schema, restore or Android identity changes.
4. After changes update `MAINTENANCE.md` with the actual outcome, tests and unresolved items. Update APP_MAP only when routes/files/contracts change.
5. Run `npm run check`. Never claim device testing when only web/CI was checked.

## Data invariants
- Preserve all user accounts, transactions, debts, budgets, settings and PINs, including IDs that resemble demo data.
- Schema migration: snapshot must succeed first; no cleanup/reset. Bump schema only on a data contract/migration change.
- Account balances and transaction history must commit together through `atomicWrite`; recover interrupted writes first.
- Reuse the fixed signing identity in `SIGNING_IDENTITY.json` (new-key transition expressly authorized 2026-10-24). No later key rotation, appId change or `localStorage.clear` in updates.
- Restore validates before writing and snapshots the current data. Invalid/future backups must not overwrite it.
- Same account transfers, missing account IDs, invalid amounts and insufficient balance must not silently record.

## Release
- Canonical app: React web bundled by Capacitor in `mobile/`. Root `android/` is a historical native prototype, not the release target.
- Version is generated by `scripts/release-version.mjs` in CI; UI reads `src/release.json`. Do not manually edit generated Gradle version fields.
- Use the fixed key backup documented in `RELEASE.md`. Missing CI secrets means unsigned compilation and private local signing with that same key; never generate a substitute.
- UI must support light/dark; new visible strings go in both language dictionaries.
